## Behavior

`scripts/operating-layer.py` now selects a canary target only when it is both changed and relevant:

- A direct verifier file reference selects that repository-relative file with source `verifier_reference`.
- `--canary-target` accepts a relative or absolute file input, validates it inside the verification checkout, and persists only a repository-relative target with source `explicit`.
- An opaque verifier has no target. It records `canary_target: null`, source `unavailable`, result `null`, and stays nontrivial.

The resolver rejects missing, non-regular, symlinked, outside-checkout, binary, unreadable, or unchanged targets. The mutation itself still restores original bytes in a `finally` block.

## Receipt Contract

Every executed proof now records `canary_target`, `canary_target_source`, `canary_target_reason`, and `canary_mutant_failed`. The selection helper keeps raw shell tokens and absolute inputs internal; the proof record receives only stable source/reason values and a repository-relative path.

The local CLI-level receipt beside this file is generated by the verifier. It proves a named changed file, an unavailable opaque verifier, and an explicit ignored target in a temporary git checkout.

## Compatibility

The prior `run_canary_mutant(verify_cmd, cwd, timeout=120)` call shape still works. `--canary-target` is optional. Existing receipts remain legacy records because they do not contain target provenance; they are neither rewritten nor relabeled.
